# Phase 0 evidence: P0-06 through P0-10

Status: implementation evidence recorded; Phase 0 exit and release promotion
remain open.

Recorded: 2026-09-07

## Acceptance mapping

### P0-06 — session-start receipt idempotency

- `internal/events/events.go` exposes a receipt identity lookup that does not
  invoke projection.
- `internal/app/app.go` performs that lookup before baseline capture for
  `session.started`.
- `TestDuplicateSessionStartedSkipsBaselineAfterRepositoryMutation` proves a
  replay returns a duplicate result and does not recapture the changed
  repository.

### P0-07 — transactional consent and durable policy

- Initialization writes a locked pending consent record before Git mutation,
  promotes it to the active policy only after Git identity verification, and
  removes it on failed initialization.
- `securefs.WithExclusiveLockWithin`, `AtomicWriteWithin`, and
  `RemoveWithin` provide anchored no-follow access, OS locking, atomic writes,
  and directory synchronization.
- Policy reads reject malformed/unknown/invalid files visibly; writes require
  exactly the next revision and reject concurrent stale writers.
- Regression coverage includes corrupt policy, stale revision, concurrent
  writer, replacement-lock symlink, successful initialization, and failed
  initialization cases.

### P0-08 — analysis closure

- CI runs pinned staticcheck and gosec versions.
- The gosec job has no broad rule exclusions. The remaining 22 findings are
  line-scoped `#nosec` suppressions with boundary-specific rationale for
  validated argv/path operations, Git SHA-1 compatibility, and redaction
  reason constants. The owner, linked tests, and review triggers are recorded
  in [`gosec-suppressions.md`](gosec-suppressions.md).

### P0-09 — contract acceptance

- [`acceptance-record.md`](../acceptance-record.md) records the named owner,
  date, accepted requirements/lifecycle/event/threat/compatibility/release
  scope, and the explicit NO-GO boundary.
- The normative documents link back to that record and no longer describe
  their implementation baseline as awaiting acceptance.

### P0-10 — release output and binary identity

- `scripts/release-build.sh` rejects an existing non-empty output directory,
  derives or accepts reproducible version/commit/date/compatibility values,
  and injects them with `-ldflags -X`.
- `version` and `doctor` report the identity without creating application
  state.
- Release integration tests prove stale-output rejection, embedded identity,
  reproducible Linux output, supported target naming/architecture, checksums,
  and unsupported-target rejection.
