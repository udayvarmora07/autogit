# Phase 2 P2-01–P2-05 evidence

Date: 2026-09-07

This bundle records implementation evidence for the five requested Phase 2
work packages. It does not close the Phase 2 release gate: the all-advertised-
adapter native matrix, upstream drift automation, provider canary, and the
Phase 1 gate remain open. Phase 0 exit acceptance is now recorded in the
[acceptance record](../acceptance-record.md#phase-0-exit-acceptance).

## P2-01 — versioned registry and fixtures

- `internal/adapters/registry.go` is the single source for adapter names,
  schema majors, client version windows, event mappings, capabilities, config
  shapes, hook events, executable names, fixture versions, and contract
  provenance.
- Registry identity is `autogit.adapter-registry/1` and is asserted by
  `docs/compatibility-manifest.json` and tests.
- Twelve embedded JSON fixtures cover Codex 0.153.x, Claude Code 2.1.x,
  Cursor 3.14.x, Gemini CLI 0.55.x, and observation-only OpenCode and
  CommandCode. Registry validation rejects malformed fixtures and
  sensitive-looking fields.
- Tests validate fixture metadata/digests and translate every fixture through
  the adapter boundary within an approved project root.

## P2-02 — bounded install and doctor probes

- Probes resolve and validate the actual executable target, including launcher
  symlinks, use a bounded `--version` process with capped output (five-second
  default, ten-second maximum), and classify
  unavailable clients as `unsupported`, failed/unknown/out-of-window probes as
  `degraded`, and recognized versions as `supported`.
- `doctor` reports all six probe results and the registry version. Client
  installation reports include the install-time probe result and registry
  identity.
- The local Linux probe run on this workstation recognized Codex 0.153.4,
  Claude Code 2.1.233, Cursor 3.14.7, and Gemini CLI 0.55.1. OpenCode and
  CommandCode were explicitly reported as observation-only/unsupported.

## P2-03 — current official hook contracts

- Codex uses the grouped `SessionEnd` hook contract and a pinned sanitized
  fixture. Reference: [Codex hooks documentation](https://learn.chatgpt.com/docs/hooks).
- Claude Code uses the grouped `TaskCompleted` hook contract, preserving the
  task identity in the translated scope. Reference: [Claude Code hooks
  documentation](https://code.claude.com/docs/en/hooks).
- Gemini CLI uses the grouped `SessionEnd` hook contract and a pinned
  sanitized fixture. Reference: [Gemini CLI hook reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md).
- Cursor uses the version-1 flat `sessionEnd` command-hook shape; its
  `afterFileEdit`, `workspace_roots`, `conversation_id`, and `file_path`
  fields are translated and tested. Reference: [Cursor hooks
  documentation](https://prod.cursor.com/docs/hooks).

## P2-04 — observation-only boundaries

OpenCode and CommandCode remain non-installable synthetic-observation
adapters. Each registry entry carries a precise reason instead of a guessed
lifecycle mapping or a fabricated native installer. Their sanitized
observation fixtures still pass the canonical adapter translation tests.

## P2-05 — safe config edits

- Grouped-hook clients preserve unrelated hook groups and use an explicit
  `name: autogit` ownership marker. Cursor uses exact command ownership because
  its documented flat command-hook object has no grouped marker field.
- Install and uninstall are constrained to explicit roots, reject symlinked or
  non-regular targets, use restrictive modes, perform stale-byte checks, write
  same-directory atomic replacements, and create exclusive backups before
  replacement.
- Tests cover idempotent install, unrelated-hook preservation, ownership
  conflicts, backup/atomic behavior, concurrent edit refusal, Cursor flat
  schema, uninstall, and malformed-hook rejection.
