## P1-04 — enforcement slice

- Descendant cleanup covers both process groups and Linux descendants that
  deliberately create a new session.
- Linux CPU, address-space, and file-size ceilings are applied with `prlimit`;
  an explicit process-count ceiling is also applied when requested. Isolated
  namespace runs apply these limits to the verifier inside bubblewrap so
  process accounting is scoped to the sandbox user namespace. The default
  process-bounded tier leaves Linux process-count unset because `RLIMIT_NPROC`
  is per-UID and would count unrelated processes owned by the caller.
- Linux filesystem-isolated and filesystem/network-isolated tiers are backed by
  bubblewrap user/pid/network namespaces, read-only runtime and allowlisted
  binds, and `--unshare-net` for network denial. The machine-readable
  capability report also probes the Landlock ABI without installing a ruleset;
  it records Landlock as detected-but-not-enforced when present, so the
  achieved primitive remains the namespace runner rather than an overstated
  in-process policy. Unsupported platforms fail closed for these stronger
  tiers. Windows reports job-object enforcement and explicitly records that
  AppContainer is not enabled. macOS reports the process-group fallback and
  unavailable resource ceilings rather than emulating them.
- Trusted verifier evidence now binds the achieved primitive, limitations, and
  capability observations into the evidence digest; reuse rejects a changed
  primitive even if the broad isolation-tier name is unchanged.
- Runtime coverage is in `internal/process/process_tree_unix_test.go`,
  `internal/process/resource_limits_test.go`, `internal/process/sandbox_test.go`,
  `internal/process/landlock_test.go`, and
  `internal/verification/isolation_test.go`.

## P1-06 — candidate-tree differential coverage

- `CompareTreeToSnapshot` compares Git's resulting tree against immutable
  expected bytes, normalized modes, and exact safe paths, and rejects duplicate,
  delete, control, newline, traversal, and unsupported entries.
- Transaction tests cover exact bytes without clean filters/hooks, executable
  modes, option-like and Unicode paths, sparse-checkout parent retention, and
  concurrent index/worktree changes.
- Repository/history tests cover linked worktrees, Unicode paths, LFS pointer
  fail-closed scanning, submodules/gitlinks, symlinks, binary content, and raw
  malformed newline paths. The policy for unsupported tree kinds is explicit
  rejection rather than reinterpretation.

## P1-07 — SHA-1/SHA-256 object formats

- Git object format is detected from `rev-parse --show-object-format`; object
  validation accepts only the repository's 40- or 64-hex-character format.
- SHA-256 transaction creation, candidate tree comparison, commit identity, and
  reachable-history scanning are exercised in real Git repositories. Existing
  state, event, provider, and lifecycle validators already accept both object
  ID lengths where the domain contract permits them.

## P1-08 — verifier executable/config identity

- Trusted registry construction requires an existing canonical executable and
  records its SHA-256 fingerprint. Execution rechecks the fingerprint.
- Linux `ExecRunner` opens and executes the verified executable object through
  `/proc/self/fd`; bubblewrap namespaces carry that object through
  `--ro-bind-fd`. Replacement between validation and execution is rejected.
- Incompatible custom launchers and other platforms use the
  `digest-rechecked-path` fallback and report that residual limitation
  explicitly in `TrustedEvidence.ExecutableBinding`.
- Trusted verifier configuration remains bounded, protected-state, no-symlink
  input and its canonical digest is included in verification evidence.

## P1-09 — policy semantics

- Tracking is explicitly three-state: `no`, `local`, and `yes` (with empty only
  for an unconfigured policy). The inconsistent `public` tracking value is
  rejected and no predicate treats it as enabled.
- Provider access and public publication require explicit `yes`; local tracking
  cannot authorize either. Table tests cover validation, merge, and all states.

## P1-10 — read-only command paths

- `status` and `logs` now resolve repository/state facts without bootstrapping
  state, and open an existing event database through a read-only SQLite handle.
  `plan`, config explain, and non-repair doctor retain their read-only paths.
- Tests verify missing-state calls create no directory, existing state bytes and
  modification time remain unchanged, repository HEAD/index remain unchanged,
  and malformed/unsupported read-only requests do not create state.
